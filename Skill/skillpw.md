## 🎯 3. Core MVP Features (สิ่งที่ต้องทำ - Must Have)

### 3.1 หน้าแรก & ข้อมูลโรงเรียน (Landing Page)
* **Identity Section:** แสดงชื่อโรงเรียน, อักษรย่อ (พ.ว.), โทนสีเขียว-ขาว, คำขวัญ, ที่ตั้ง และระบุชื่อ **คุณยายจาด พูลเจริญ** ในส่วนประวัติการจัดตั้ง
* **Floating CTA Button:** ปุ่ม **"สมัครเรียนออนไลน์"** แบบลอยตัวติดหน้าจอ (Floating Button) ที่ผู้ใช้สามารถกดได้ตลอดเวลาจากทุกหน้า
* **Contact & Social Links:** แบบฟอร์มส่งข้อความสอบถาม พร้อมลิงก์ไปยังโซเชียลมีเดียและเว็บไซต์ทางการ

### 3.2 หลักสูตร ม.4 & ข่าวสารกลุ่มสาระ (Curriculum & News)
* **หลักสูตรชั้น ม.4 (เป๊ะตามข้อมูลจริงทั้ง 9 ห้อง):**
  1. **ห้อง 1:** ห้องเพชร (ห้องพิเศษ/ความเป็นเลิศ)
  2. **ห้อง 2, 3, 4:** ห้องวิทย์-คณิต
  3. **ห้อง 5:** ห้องศิลป์คำนวณ
  4. **ห้อง 6:** ห้องศิลป์ภาษา (แยกเป็น 2 สาขา: 1. ภาษาอังกฤษ, 2. ภาษาฝรั่งเศส)
  5. **ห้อง 7:** ห้องจีน-ญี่ปุ่น
  6. **ห้อง 8:** ห้องคอมพิวเตอร์-ธุรกิจ
  7. **ห้อง 9:** ห้องการงานอาชีพ
* **ระบบติดตามข่าวสารตามกลุ่มสาระ:** มีพื้นที่แสดงข่าวสาร ประกาศ และกิจกรรมแยกตามกลุ่มสาระการเรียนรู้

### 3.3 ระบบรับสมัครเรียนออนไลน์ (Online Application Flow)
* **Application Form:** ฟอร์มกรอกข้อมูลส่วนตัวผู้สมัคร ข้อมูลผู้ปกครอง และช่องดร็อปดาวน์เลือกสายการเรียน ม.4 ทั้ง 9 รูปแบบ
* **File Upload:** ฟังก์ชันจำลองหรืออัปโหลดไฟล์เอกสารสำคัญ (เช่น รูปถ่าย, ปพ.1)
* **Review Page:** หน้าจอสรุปข้อมูลให้ผู้สมัครตรวจสอบความถูกต้องก่อนกดปุ่มยืนยันการสมัคร

### 3.4 ระบบแจ้งผล & ตรวจสอบสถานะ (Status Tracking)
* **Application ID Generation:** แสดง **"เลขที่สมัคร"** บนหน้าจอทันทีเมื่อกดยืนยันการสมัครสำเร็จ
* **Status Checker:** หน้าค้นหาและตรวจสอบสถานะการสมัคร โดยใช้เลขบัตรประชาชน หรือ เลขที่สมัคร เพื่อแสดงสถานะปัจจุบัน (เช่น *รอตรวจสอบเอกสาร / ผ่านการคัดเลือก*)

## ⛔ 4. Strict Constraints (ข้อห้ามและสิ่งที่ห้ามทำ)

1. **ห้ามทำระบบหลังบ้านแอดมินที่ซับซ้อน (No Admin Dashboard):** ให้ใช้ Mock Data หรือจัดการสถานะผ่าน Database โดยตรงไปก่อน
2. **ห้ามเชื่อมต่อ API ภายนอกที่ซับซ้อน (No Third-Party Integration):** งดการต่อระบบส่ง LINE Notify หรือ Email Gateway จริง ให้เน้นแสดงเลขที่สมัครบนหน้าจอทันที
3. **ห้ามทำระบบ Authentication/User Login:** ไม่ต้องให้ผู้สมัครสร้างบัญชีผู้ใช้ แต่ให้ใช้ "เลขบัตรประชาชน" หรือ "เลขที่สมัคร" ในการค้นหาข้อมูลแทน
4. **ห้ามเสียเวลากับ Custom CSS ยุ่งยาก:** ให้ใช้ Tailwind CSS หรือ UI Framework เพื่อความรวดเร็วในการพัฒนา

## 🛠️ 5. Technical Guidelines & Workflows
* **Mobile-First & Responsive:** ออกแบบ UI ให้ใช้งานง่าย ลื่นไหลทั้งบนหน้าจอมือถือและคอมพิวเตอร์
* **Clean Components:** แยกส่วน Component ให้ชัดเจน (เช่น `Header`, `Footer`, `FloatingCTA`, `CurriculumCard`, `ApplicationForm`, `StatusChecker`)
* **Focus on MVP:** พัฒนาเฉพาะฟีเจอร์ที่อยู่ใน Scope นี้เท่านั้น ห้ามเพิ่มฟีเจอร์นอกเหนือจากที่กำหนด
